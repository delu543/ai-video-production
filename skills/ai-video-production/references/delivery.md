# 验收与交付

## 四类验收分开

| 类别 | 证据 | 不能替代什么 |
|---|---|---|
| 技术 | FFprobe、完整解码、帧数/时长/SAR/音轨、最终 loudnorm | 不能证明文案好、音乐合适 |
| 内容 | 事实账本、旁白/镜头逐段对应、出处/日期、原话上下文 | 不能证明清晰度与播放听感 |
| 动态视听 | 实际带声播放、每个边界、关键演示、首中尾帧、耳机/扬声器 | 联系表/静态截图不能代替 |
| 发布条件 | 每项素材使用依据、署名、音乐证明、目标平台与预算 | 本地导出不等于具备公开发布权或已发布 |

## 必须通过的门

**技术**：目标尺寸/帧率、SAR=1:1、无拉伸；H.264/yuv420p、AAC 48kHz 通常兼容；CFR；视频帧数等于主时间线（全局边界统一四舍五入）；音频时长对应；完整解码无错误；预留编码后真峰值；开头/结尾正常。针对 HDR 另用正确转换流程。

**素材**：所有镜头本地存在、源时段足够、原文件可溯源；实际清晰度检查通过；现代低清预览替换；档案例外写明；默认最多两次使用，例外有理由；无意外水印/播放器/原片片尾。

**逻辑**：每句关键事实有具体画面；发布/演示不由官网首页代替；所有边界有关系与切法理由；没有无关素材之间直接跳；使用直接切不等于失败，但没有依据的切是失败。

**画面**：无上下黑条遮罩、叠字、双影、字幕挡证据、盲目裁切与黑帧；照片与档案融入画面；动效准确克制；条件/数据按理解顺序展开，关键停点和静态取帧没有半行、半字或被遮住的数值；参考学习不是抄截图。允许的生成说明图核查用途、提示、文字与图形比例。

**声音**：声线/语言符合已选方向；自然青年讲解而非电台腔或轻佻；数字/专名正确；原音同步与上下文准确；BGM音色情绪与内容统一，没有无依据的机械脉冲/装饰声；保留合理同期声与拟音且不混淆来源；密集解释/原话与计划无乐窗口可听清；换曲/包络无突跳，结尾有自然尾声。

**文案**：年份、人物、机制、变化齐全；技术解释清晰；事实/判断/未来未知区分；有思考但不挤掉信息；结尾从前文推导而不是口号。

## 对最终文件检查，而非只检查中间产物

- 预览要覆盖实际片中的格式变化、档案与现代影像切换、照片、原声窗口、最长字幕及复杂转场；单一素材的短测试不能代表混合来源的长片。
- 核对主时间线帧数、最终解码帧数与时间戳。平均帧率接近目标或总时长正确，仍可能藏有间隔不均、丢帧或重复帧；有异常就检查逐帧/逐包时间戳和导出计数，不能补冻帧后声称原问题已解决。
- 混音通过后还测实际 MP4 的压缩音轨：综合/段落响度、真峰值、原声同步与尾声。没有计划外整幅黑场、冻结或静音；计划内淡黑、留白要与主时间线比对，不当作故障一律删去。
- 查看实际带字幕的编码画面，不能只看原片或静音合成。联系表、边界前中后抽样与像素回归各自注明范围，不代替连续带声播放或主观听审。
- 修正范围决定复查范围。只改配乐/混音、旁白字幕时点不变时，可复用已执行的正文画面审阅；保存cue比较与画面一致性证据，新封装仍检查解码、帧数/PTS、音轨、时长、最终AAC响度/峰值、改变的声音区间及前后入出。更换配音时必须重查时间轴，不能复用旧同步结论。
- H.264复制再封装/拼接可能插入参数集，逐包哈希不一致不能单独证明画面变了。需要精确确认时比较实际解码帧哈希或受控的像素结果，注明区间；不能据此跳过连续播放，也不能只凭文件总大小相近宣称未变。尾页更新署名后单独检查实际编码文字与拼接边界。

## 报告与版本

`qa` 生成客观技术结果与 `editorial / visual / listening` 的未审阅占位。执行者完成真实审阅后填写结论、证据位置和发现的问题；不允许程序把这些字段默认为 passed。

默认完整交付包含可播放MP4、独立旁白WAV（有旁白时）、SRT字幕、可编辑主工程、最终分镜、媒体许可台账、事实来源与实际计算记录；另附成本和技术/视听验收说明。无旁白或不涉及计算时如实标注适用范围，不造空文件。需要交接原素材时先核对其分发许可。用户只要视频也应内部保存工程与证据，最终回复突出成片。

文件名清楚且稳定，旧版不覆盖；记录版本、工程哈希、工具版本与已修改范围。最终链接必须指向真实输出，不展示不存在的文件。尚未完成的发布授权/人工审阅单独说明，不能以“世界级”“完美”替代验收。

## 常见技术根因

- 相邻淡化必须规范 fps、timebase、尺寸、像素格式和 SAR；混合 VFR 直接串 xfade 容易失败。工具先规范素材，再用帧数明确的 blend 合成。
- 源时间不足不能无限 tpad；检查 source_in、播放速度与转场余量，缺素材先换镜头。
- 累加各段独立取整可能漂移；使用累计时间边界计算帧数。最终编码有一帧误差先追查，不用大段冻帧掩盖。
- 缓存依赖包括源文件哈希、左右镜头、构图、字幕、参数和工具版本；改右镜头必须重算左边的转场。局部预览不能当作完整缓存：复用前核对对应主工程、指纹、实际时长/帧数与所需区间，不按文件名或修改时间猜测。
- loudnorm JSON 后可能附带日志，解析首个对象而非把全部 stderr 当 JSON；二遍测量与应用条件一致。
- ASS 字符与滤镜路径需要转义；多语缺字要实际渲染检查；音画帧轴是唯一主轴。
- 分辨率/帧率相同不代表解码属性相同：色域、色彩范围与像素格式变化也可能让滤镜重建。先规范输入，检查跨格式预览；已经验证为CFR的主画面不要无必要再叠缓冲式fps。局部预览的时间戳处理不能在滤镜重建时重置主轴。
- 自定义淡经黑场时，不能把YUV三个分量一起乘到0；色度的中性值不在0。可在RGB中合成再转换回目标像素格式，查看黑场中点及两侧，避免绿色/偏色转场。这个专项效果需要相应渲染适配，不由普通交叉淡化自动提供。
- 编码后真峰值超标先修音频/编码余量；字体有字不等于可读，要确认实际字重、字形与安全区域；错误/登录HTML即使下载成功也不是有效媒体。

滤镜与检测参数以 [FFmpeg官方文档](https://ffmpeg.org/ffmpeg-filters.html) 为准。这些是诊断原则，不代表CLI已自动识别所有摄影、音乐或主观质量问题。

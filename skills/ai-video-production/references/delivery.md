# 验收与交付

## 四类验收分开

| 类别 | 证据 | 不能替代什么 |
|---|---|---|
| 技术 | FFprobe、完整解码、帧数/时长/SAR/音轨、最终 loudnorm | 不能证明文案好、音乐合适 |
| 内容 | 事实账本、旁白/镜头逐段对应、出处/日期、原话上下文 | 不能证明清晰度与播放听感 |
| 动态视听 | 实际带声播放、每个边界、关键演示、首中尾帧、耳机/扬声器 | 联系表/静态截图不能代替 |
| 发布条件 | 每项素材使用依据、署名、音乐证明、目标平台与预算 | 本地导出不等于具备公开发布权或已发布 |

## 必须通过的门

**技术**：目标尺寸/帧率、SAR=1:1、无拉伸；H.264/yuv420p、AAC 48kHz 通常兼容；CFR；视频帧数等于主时间线（全局边界统一四舍五入）；音频时长对应；完整解码无错误；预留编码后真峰值；开头/结尾正常。针对 HDR 另用正确转换流程。

**素材**：所有镜头本地存在、源时段足够、原文件可溯源；实际清晰度检查通过；现代低清预览替换；档案例外写明；默认最多两次使用，例外有理由；无意外水印/播放器/原片片尾。

**逻辑**：每句关键事实有具体画面；发布/演示不由官网首页代替；所有边界有关系与切法理由；没有无关素材之间直接跳；使用直接切不等于失败，但没有依据的切是失败。

**画面**：无上下黑条遮罩、叠字、双影、字幕挡证据、盲目裁切与黑帧；照片与档案融入画面；动效准确克制；参考学习不是抄截图。

**声音**：声线/语言符合已选方向；自然青年讲解而非电台腔或轻佻；数字/专名正确；原音同步与上下文准确；BGM 调性与内容统一；密集解释/原话窗口可听清；换曲/包络无突跳，结尾有自然尾声。

**文案**：年份、人物、机制、变化齐全；技术解释清晰；事实/判断/未来未知区分；有思考但不挤掉信息；结尾从前文推导而不是口号。

## 报告与版本

`qa` 生成客观技术结果与 `editorial / visual / listening` 的未审阅占位。执行者完成真实审阅后填写结论、证据位置和发现的问题；不允许程序把这些字段默认为 passed。

交付可播放 MP4，独立字幕，文案/分镜，来源与许可表，成本说明，技术与视听报告；可编辑工程保留本地。需要交接原素材时先核对其分发许可。用户只要视频也应内部保存这些证据，最终回复突出成片。

文件名清楚且稳定，旧版不覆盖；记录版本、工程哈希、工具版本与已修改范围。最终链接必须指向真实输出，不展示不存在的文件。尚未完成的发布授权/人工审阅单独说明，不能以“世界级”“完美”替代验收。

## 常见技术根因

- 相邻淡化必须规范 fps、timebase、尺寸、像素格式和 SAR；混合 VFR 直接串 xfade 容易失败。工具先规范素材，再用帧数明确的 blend 合成。
- 源时间不足不能无限 tpad；检查 source_in、播放速度与转场余量，缺素材先换镜头。
- 累加各段独立取整可能漂移；使用累计时间边界计算帧数。最终编码有一帧误差先追查，不用大段冻帧掩盖。
- 缓存依赖包括源文件哈希、左右镜头、构图、字幕、参数和工具版本；改右镜头必须重算左边的转场。
- loudnorm JSON 后可能附带日志，解析首个对象而非把全部 stderr 当 JSON；二遍测量与应用条件一致。
- ASS 字符与滤镜路径需要转义；多语缺字要实际渲染检查；音画帧轴是唯一主轴。

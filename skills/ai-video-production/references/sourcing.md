# 素材：匹配、清晰度与真实性

## 先匹配，再下载

每个叙事单元写：旁白核心事实、需要看见的对象/动作、优先来源、候选入出点、用途（证据/解释/环境/情绪）、替补。按“人物+事件+年份+演示/采访/档案”等中英文组合查找，不只搜抽象的“科技”“未来”。

优先顺序通常是：实际现场/产品演示→机构原始档案→当事人采访/可靠新闻→高质量相关实拍→有来源照片/原始文献。具体顺序依题材调整。事件发生时的声音和镜头，常比一段漂亮但无关的通用视频更有价值。

例：谈某模型的实时交互，找该版本的真实交互过程；谈开发者大会，找台上的宣布、具体产品演示与观众现场，而非首页或会标。长视频先看章节/官方字幕定位，再看前后语境，截最能说明文案的一小段。产品宣传片选择体现真实功能的核心操作，不只选旋转 Logo。

## 全网拓展的操作

1. 在 [source-catalog.md](source-catalog.md) 选择与题材相关的 3–5 类入口，不固定在两个实拍站。
2. 网页检索找到内容页，回到原发布者/机构/摄制者查原始版本。平台、转载号与搜索引擎缩略图都不是原文件。
3. 下载许可范围内最高质量的适用版本。YouTube/发布会检查实际可用的视频与音轨格式、分辨率、帧率；采用成熟工具或官方媒体包，不编写绕过访问控制的抓取器。
4. 保存本地原文件与哈希；查看首段、中段、尾段及动作关键时点。下载成功不代表内容正确。
5. 记录 `source_url / creator / recorded_date / depicted_date / license_url / rights_status / local_path / source_in / used_duration`。
6. 确认实际可用后才锁定分镜。少数不可获取的片段换等价高质量证据，不用低清预览凑数。

## 有效画质门

| 项目 | 默认要求与检查 |
|---|---|
| 现代全幅实拍 | 优先原生 1080p 以上，尽量使用 4K 原片；无严重压缩、失焦、噪点、锯齿、水印/播放器 UI |
| 裁切 | 用裁后像素判断，4K 画面中的 300 像素手机仍是低清。放大、裁切与稳定都减少可用像素 |
| 清晰度 | 看人脸、文字、物件边缘与移动画面；`width/height` 不能证明原生细节，超分版本也需明示与实看 |
| 色彩/质感 | 曝光正常、肤色可信、明暗层次完整；不要全片罩统一重绿/重橙滤镜 |
| 历史档案 | 寻找馆藏扫描/修复/官方较高质量版本；稀缺原始记录可保留颗粒，但必须标注档案性质、限制作例外，不把烂清晰度当“复古” |
| 图像/文献 | 下载原尺寸，不用搜索缩略图；关键文字要在成片中读得见；证明具体事实的照片优于无关高清视频 |
| 竖屏/4:3 | 保内容构图，背景柔化/简洁版式；不拉伸，不把窄画面盲目裁成全幅，不用黑条充当电影设计 |

工程 `quality` 记录裁后有效尺寸、可见区域、人工检查状态及 `exception_reason`。保内容的小幅档案不按全幅输出分辨率机械淘汰；按实际显示区域检查，并人工确认其细节。现代低清库存不能用“例外”逃过替换。

## 丰富而不重复

- 每个新人物、制度、技术节点尽量有对应独立素材。素材数量服务信息变化，不强制某个数量。
- 同一素材默认最多两次，不连续来回使用；第二次必须有新功能/不同入点或明确回环意图。照片、整段采访、同一长发布会都按源资产归组统计，不能改文件名规避。
- 原片的不同镜头可以构成一次连续使用；多个节点必须依赖同一原始记录时写明例外理由和低频安排，不能为了计数改写来源。
- 同类场景切换景别、动作、视角和主体；不要十个机房镜头代替十个不同技术。
- 架构图、标题、地图和图表可作为准确说明；不使用生成画面假扮实拍，不抄参考视频画面，不将图片逐页闪过。

## 许可分离

记录具体素材的商用/编辑使用、署名、衍生、地区/时长限制、人物/商标限制与证明。免费访问、公开视频或“免版税”不等于免费再利用。电影、综艺、新闻可以检索参考，但使用必须取得适用许可或已明确的使用依据；不存在统一“截几秒就合法”的门槛。

许可待核实的候选可以进入内部设计，公开发布前替换或取得对应授权。成片报告列出待核实项，不能将这样的版本标为已具备完整发布权。来源记录和原文件不得作为“开源素材包”上传到工作流仓库。

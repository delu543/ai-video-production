# 许可、项目数据与交付权利

## 开源范围

本 Skill 的代码、文档与工作流规则按 MIT 提供，复制/分发时保留版权与许可声明。仅 `assets/brief.example.json`、`assets/project.example.json` 这两份自有示例数据适用 CC0-1.0，范围及全文随安装包提供。新增数据不自动继承 CC0，需有明确的逐文件记录。

实际项目的输入与输出、第三方工具/字体/素材以及外部服务条款分别核对。不能把“工作流是 MIT”写成“生成影片所有素材都可任意商用”。示例模板的许可不重新授权填入模板里的客户资料、原话、媒体或摘录。

## 逐项媒体记录

记录：素材ID、原始内容页、作者/权利方、取得日期、原始时间、使用依据链接、证明位置、允许发布平台、商业使用范围、署名文本、改编/再分发限制、源入出点和成片使用时间码、当前核查状态。视频、照片、音乐、原音及后期拟音/环境音均入账。区分：

1. 工作流源代码与示例数据的复用。
2. 本地研究/预览中使用候选素材。
3. 将媒体剪入最终影片并公开发布。
4. 将工程及原素材另外交接/再分发。
5. 把内容用于训练或其他二次用途。

这些不是同一个权限。公开视频、免费下载与短片段不直接证明后四项都获准。电影/综艺/新闻、库音乐与采访按实际依据处理；许可不明先替换或查证，不把可能适用的例外写成统一法律结论。

换音乐时新版本的台账、片内尾页与发布署名都对应实际曲目；旧许可作为历史证据保留，不再出现在新版本的活动使用清单。需要新付费授权先列明对象、范围和费用，不擅自采购；免费取得文件也要完成权利核查。不得裁水印、镜像、变速或改文件名来掩盖来源/授权缺口。

## 数据处理

默认工程与素材留在本地、仓库外；CLI 不上传、不自动训练。调用外部服务仅发送已授权且完成任务必要的数据，记录服务与输入类别；服务保留、再训练、地区、商用与输出权利查询当前官方/账户条款。不能宣称所有 API 都不保留数据。

真实项目数据不提交 GitHub、公开 Issue、公开日志或测试夹具。开源仓库的测试使用合成数据，不能把合成测试夹具改标为真实素材。声线克隆、可识别人像和原音采访要有对应对象/使用授权；拥有文件本身不是授权证明。

## 交付与发布门

影片、字幕、文案、来源表、工程与原素材逐项确认交付/分发范围。署名写入成片/说明的方式符合单条要求；保留音乐证明与可能的 Content ID 处理信息。许可待核实的版本仅标明其实际状态，不能给“可无条件发布”的结论。

检查项目来源表与目标用途，确认许可、隐私/声音/肖像和必要服务条件，再执行用户已授权的发布。未获授权时仅本地交付。开源仓库改动不改变已有项目的保留/删除约束。
